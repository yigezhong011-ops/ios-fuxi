
## 2026-10-26 凌晨 —— 显示链路打通 + 用户态重做（重大进展）

### 今天拿下的四件事

1. **GPU 加速器真正起来了**
   - 补丁 `0111-fuxi-gpu-zap-optional.patch`：ZAP 自检（0xf07）不再一票否决。
     ZAP 只用于受保护内容，普通合成不需要。
   - 结果：`FUXI GPU: ready` → `NativeAdrenoGpuPublished` → backboardd 匹配成功
   - SpringBoard 崩溃从 60 次降到 **0 次**

2. **用户态换成正确的 iPhone X (D22AP) iOS 16.7.11**
   - 根因：之前是 iPadOS 用户态，资源库没有 iPhone X 的圆角遮罩
     `BoundingPathBitmap-1125x2436-375x812-3.00x` → SpringBoard 断言崩溃
   - 从 IPSW 提取 `DeviceTree.d22ap.im4p`（LZFSE）→ `research/ipsw-x/d22ap.adt`
   - `mkadt-fuxi.py` 现在带 `/product` 节点（ADT 从 10240 → 12372 字节）
   - 新 root 由 `mkiosroot.sh` 从 iPhone X 的 OS/SystemOS/AppOS.dmg 重建

3. **面板扫描输出打通（今天最大的突破）**
   - 三个串联的 bug：
     a. `fuxi_display_kick()` 只在 CTL0 START 位为 0 时才写；这机器上该位一直是 1
        → 补丁 `0112` 改成每次都写（最小单 hunk，`git apply` 已验证）
     b. `sweet_surface_gpu_copy()` 每次都返回 2（上一帧 inflight 未回收）
        → 每帧跳过 CPU 拷贝，画面永远不动
        → 补丁 `0114` 在函数入口直接 `return 0`，强制 CPU 拷贝
     c. cmdline 缺 `fuxigpuscanout=1`，GPU scanout 没启用
   - 结果：`FUXI SCANOUT: frame=N path=CPU bytes=10368000 copy_us=6167`
   - **屏幕上第一次出现真实画面**（苹果 logo + 进度条、内核控制台日志）

4. **建立可复现的完整流水线**
   - 根镜像：`mkiosroot.sh` (OS/SystemOS/AppOS.dmg) + `sweet-root-tweaks.py`
   - ADT：`mkadt-fuxi.py --live-fdt --root-extents --gpu-reserve --smp`
   - 内核：CI（fork `pyhs5g27vr-hue/ios-fuxi`，workflow 395549366）
   - 打包：`step24c-build-final.sh`（ext-new2.json = 18 段 extents）
   - 启动：`fastboot boot fuxi-diag.img` + `fuxi-xnu-monitor.py`

### 下一步建议

3. 如果仍卡住：在 `sweet-root-tweaks.py` 里做**增量**开关，逐项验证是哪个 tweak 让
   SpringBoard 起不来（真凶很可能是 purplebuddy 的 SetupDone 与 mobileactivationd 的冲突）
